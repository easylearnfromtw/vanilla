# Vanilla · Tone Adaptation & Self-Build Studio

## 目標

Vanilla 不應只是一個套殼聊天機器人，而是能逐步貼近使用者表達方式、讓使用者用自然語言快速添加新功能的本地優先 AI 工作區。

這一版新增兩個模組：**Tone Adaptation** 和 **Self-Build Studio**。

### 語氣適應：如何真正作用於回答

- 一般模式傳送訊息後，由裝置端分析訊息長度、疑問句比例、標點／表情符號使用習慣，**只儲存數值統計**，不保存學習用的原始文字。
- 私密模式不提供語氣訓練資料；關閉語氣學習後立即停止更新統計。
- 系統設定提供直接程度、親切程度與回覆詳略滑桿，以及輕度／自然／接近三種適應強度。
- AI 回答下方可以選「語氣很像我」「太正式」「太囉嗦」「太冷淡」，作為顯式偏好回饋。
- WebLLM（iPhone 本地 AI）、Ollama 以及 Gemini／DeepSeek 的每次回答均會取得當下的語氣描述提示詞。只有允許雲端回答時，該描述才會隨模型請求送到雲端。
- 語氣學習不改變模型權重，也不代表 Vanilla 能推斷使用者的個人身份、精神狀態或真實情緒；以訊息中明確表達的當下意圖為優先。
- 使用者明確要求不同語氣／格式時，**當次指令優先**。準確性、安全規範、隱私限制不得因語氣模仿而降低。

### Self-Build Studio：新增功能流程

1. 直接在 Vanilla 聊天輸入 `新增功能：家庭記帳追蹤器，紀錄日期、金額、類別`，或由左側選單開啟 **Self-Build Studio**。
2. 選擇 AI 模型（本地 WebLLM／Ollama／Gemini），使用外部服務前需確認此次功能構想會送出。沒有可用模型時可使用本地安全模板。
3. Vanilla 產生**結構化功能規格 JSON**，僅支援 4 種安全類型：
   - `checklist`：待辦事項／每日習慣清單，可新增、勾選、移除、匯出。
   - `tracker`：結構化紀錄（文字、日期、數字、核取方塊），可以新增、檢視、刪除、匯出 CSV。
   - `calculator`：自訂欄位和四則運算公式（`+`、`-`、`*`、`/`、括號）。
   - `notes`：可編輯的本地文字筆記，支援匯出 TXT。
4. 所有 AI 方案經 `validateFeature` 安全驗證，顯示名稱、欄位、公式與原始資料保留風險。**按下確認安裝後**才加入 Vanilla 側邊欄。
5. 功能資料與功能規格分開儲存；再次要求 AI 改進已有功能時，先生成下一版方案，使用者確認才升級。每個功能保留最多 8 份已批准的規格快照，可回復上一版。
6. 對於不再使用的功能可以只移除模組，或經過兩次確認**永久刪除本機模組與資料**。

### 安全邊界（非常重要）

此版 Self-Build 是「受限的可執行模組生成」，**不是任意自動改寫自己的 React/GitHub 原始碼**。

- AI **不能**直接執行產生的 JavaScript、HTML、`eval`、動態匯入、shell 指令或 GitHub API。
- AI JSON 中未知的欄位（例如 `script`、`permissions`、`apiKey`、`endpoint`）不會成為可執行能力。
- 計算器有獨立的安全算式解析器，不執行 JS 表達式。
- Self-Build 的自建工具不得讀取其他模組的資料或 API Key。
- 所有資料目前只保留在裝置的 `localStorage`，且不是端對端加密；不要當作正式醫療紀錄或財務資料庫使用。
- 新增外部 API、Google Drive 寫入、GitHub 原始碼修改、身份與權限、3D 引擎等**需要原始碼級變更**的需求，只會產生 Markdown 工程方案與可由使用者確認的 GitHub Issue 連結。
- 原始碼自動修改的下一階段應由專用後端 GitHub App／Actions 從 Issue 建立獨立分支及 PR，跑 TypeScript／測試／安全審查，**只有使用者明確核准才允許合併**。不得授權前端持有長期 GitHub 寫入憑證，更不得自動合併 main。

### 測試與版本

- `npm run test:builder`：結構化模組驗證、JSON 沙箱拒絕任意程式、功能安裝與版本回復、私密模式不學習語氣。
- `npm run test:workspace`：原有表格公式與檔案指令回歸測試。
- `npm run build`：TypeScript 和 Vite 編譯。
- GitHub Actions 依序執行測試與部署。若部署失敗，不能宣稱新功能已上線。
