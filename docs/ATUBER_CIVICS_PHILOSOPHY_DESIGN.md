# 阿土伯 × 公民與哲學：權限治理、認識論、邏輯與公平排程

> 2026-10-21。此文件是經過程式架構對照的設計提案，**不是把政治／哲學學派當作 LLM 加速演算法**。第一目標仍是前景流暢、模型品質和可控性。

## A. 公民知識能真正改善什麼？

| 公民／制度原則 | 可執行機制 | Vanilla 已有部分 | 優先 / 注意 |
|---|---|---|---|
| 法治、明確授權 | 最小權限：工具無明確授權不得執行刪除、付款、部署；API key 分權 | Detroit/Zeus/Ceres/Quirinus 等權限界線 | P0 安全；不可被 prompt 自行繞過 |
| 權力分立、相互制衡 | 企畫者 Diana、執行者工具、驗證者 Quirinus/LUCA；**高風險行動不得由同一模型自行核准** | 已有多模組設計 | P1；不為低風險工作重複啟動 LLM |
| 正當程序 | 高風險前向使用者明示目的、影響、撤銷/回滾方法；保留操作結果 | 需要後端審計與明示確認 | P0 安全 |
| 比例原則 | 用「必要、適當、侵害最小」限制工具資料存取與系統干預 | 私密模式、裝置端選項 | P1 |
| 地方自治／補充性原則 | 讓簡單決策在本機完成；真正需要遠端資源才調度 Slime，且不得違反同意邊界 | 本地優先路由 | P1，減少網路/常駐負擔 |
| 公共財及共享資源治理 | 共享 Slime 配額、節點授權可撤回、反飢餓隊列、保留前景資源 | Slime/Telegram 管理 | 多人時 P2；0.6B 單機不需複雜競價 |
| 多元與基本權 | 不因政治意見、身份或不同背景而降低模型品質／工具權限（除確有政策或法規限制） | 中立與權限設計 | 安全原則，不是推論提速方法 |

公民知識最有價值的改進是**治理**：阿土伯知道「能做」和「有權做」並不相同。這提升可控性與信任，不保證每秒 token 增加。

## B. 哲學研究對模型的可落地價值

| 學派／方法 | 具體功能 | 成本／風險 |
|---|---|---|
| 亞里斯多德邏輯、現代命題邏輯 | 關鍵論證拆成主張→前提→推論→可反駁條件；規則型輸出契約驗證 | 大型形式證明需額外計算，僅在必要時使用 |
| 蘇格拉底詰問 | Merlin 只在缺少決定性資訊時問一個重要問題；避免無限反問 | 不要把正常對話變成審問 |
| 波普的可否證性 | 每項「AI 更快」宣稱綁定基線、反例、測試和回滾門檻 | 是驗證方法，不是模型加速技巧 |
| 奧坎剃刀（節約原則） | 優先擴充現有 runtime，避免新增 Wormhole、Blackhole、核能等常駐管理模型 | 簡化須有邊界，不能刪除安全或必要證據 |
| 認識論／證據階層 | 明確分離「來源已確認、模型推測、未知」；工具無資料時不得稱已讀 | 有時增加答覆長度，但提高可信度 |
| 貝葉斯信念更新（數學化認識論） | 透過實測資訊更新模型成功率預估；多證據來源不能錯當相互獨立 | 不能把主觀置信度當機率校準 |
| 康德義務論 / 結果論兩種倫理視角 | **安全與授權作硬約束**，其餘性能與效率在合規範圍內最佳化 | 不追求哲學流派單一真理 |
| 羅爾斯公平正義／無知之幕 | 考察各類任務與慢節點使用者是否被排程長期忽略 | 多人 Slime 才有較強的實用性 |
| 漢娜·鄂蘭對責任與權力的問題意識 | 高影響操作要可追溯、有真正人類決策者 | 哲學啟發，不是直接演算法 |
| 實用主義（Peirce / James / Dewey） | 小規模 AB、真機資料、保留有效方案；與墨家三表相呼應 | 防止過度調參和資料選擇偏差 |

## C. 與已提出的腦神經／中國思想／諾貝爾／心理學等融合

```text
使用者問題
  ↓
[公民權限閘門]      私密/高風險工具必須有授權（禁止 LLM 自我批准）
  ↓
[庖丁 + 心理學]      結構化的必要上下文（避免過度認知負荷與 prefill）
  ↓
[蟲洞 Wormhole]      精確相同前綴的 runtime 原生 cache（引擎支援時才用）
  ↓
[孫子 + 防卡頓]     GPU/Worker/main-thread 隔離、壓力感知、有限併發
  ↓
[阿土伯 Qwen3 0.6B]  只有真正必要的生成任務才佔運算資源
  ↓
[桐城白話 + 邏輯]   回答有物有序、證據可追溯
  ↓
[LUCA + 墨家 + 波普] 性能與真實性測試，通不過可回滾
  ↓
[黑洞 Blackhole]    安全回收過期快取、離線清理；不刪使用者儲存資料
```

這是一份**層次圖，不是八個獨立 AI 服務**。在 0.6B 單機場景，許多步驟應為低成本的確定性規則，而不是再執行另一個大語言模型。

## D. 哪些決定馬上實作、哪些暫緩？

**現在的 P0／P1 實際重點**
1. 背景 Worker 失效時不得靜默移至 UI 主執行緒；手動相容模式例外。
2. 只在本地生成進行時，暫時性採樣前景 p95 frame time，控制 React 串流文字更新頻率。
3. 安全的 exact-source 去重；不同來源或版本不可因「語義相似」而被當成相同內容。
4. LUCA 只記 bounded aggregate samples：模型名、毫秒、frame p95、完成狀態；不存原始問題、回答、身分或 token。
5. 完整 CI regression 和真機檢查後才宣稱改善多少幀；任何性能優化不得破壞授權、安全或來源可追溯。

**研究中，不宣稱已完成**
- 完整通用的 KV Cache 持久化／跨 session 重用：必須先證實 WebLLM/Ollama 真正支援的 API、token 精確相容及隔離。
- GPU 驅動級資源預留與硬體搶占：一般 WebGPU 程式不能保證硬性 GPU 配額。
- 哲學式「邏輯推理加速器」：哲學論證模板可改善輸出品質，但也可能增加 token；只有通過效能/品質雙門檻才整合。
- 社會式公平排程：先有多工作負載及節點，不要讓分配器成本超過本機 0.6B 工作量。

## E. 錯誤防止與哲學界線

- 模型可引用多種倫理學框架，但**不得形成自己未經授權的政治主張或權限政策**。
- 「奧坎剃刀」不是可不做證據核驗的理由；「波普可否證」也不等於拒絕統計支持的知識。
- 「權力分立」實作是不同程式權限及獨立驗證，不是讓同一個 LLM 扮演三種角色就算分權。
- 「公正」不能用惡意持續佔用資源的請求壓垮其他用戶；需 rate limit、permission gating、aging。
- 任何新增功能都必須能完全關閉，不得在未經同意下擴張數據蒐集或將私密資料傳送遠端。
