# Merlin 主動澄清與追問

Merlin 現在具備兩層保守的需求釐清：

1. **確定性前置守門**（`src/detroit/merlin-clarifier.ts`）：缺少刪除對象、只有「幫我做／這個」、要求翻譯但未提供原文且沒有可用上下文時，優先在聊天中問一個具體問題，不浪費模型 API、不憑空猜測。
2. **模型語意補充**（`src/ai/prompts.ts`）：對不在明確規則內、卻缺少關鍵資訊的問題，選定模型應優先釐清；可採安全合理假設的情況則直接完成，不應機械式問卷。

## 對話流程

- 使用者輸入「幫我翻譯」→ Merlin 提問「你要處理哪段文字或文件？」→ 使用者貼上原文 → Vanilla 將原始需求與補充輸入一同送往原有路由及模型流程。
- 使用者輸入「幫我刪除檔案」→ Merlin 要求明確指定目標；回覆名稱只用於判定目標，仍須遵守原有刪除確認與權限邊界，**不構成授權**。
- 使用者回覆「不知道」→ 再說明缺什麼；輸入「取消」→ 退出待澄清狀態。
- 已提供附件或有效先前對話時，不因為短句就一律追問；普通明確問題直接處理。
- 待追問狀態透過既有聊天紀錄中「原始訊息 ID」恢復，重新整理或開啟同一對話後可以繼續；切換私密模式及新對話會清除目前追問狀態。

## 邊界

這不是額外的 LLM 推論，也**不是經過校準的理解信心分數**。第一層僅辨識高確定性的資訊缺漏；其餘交由現有模型判斷。未額外儲存問題副本或呼叫第三方澄清服務；對話仍依 Vanilla 原有的本機保存、帳號與私密模式規則處理。

驗證：`npm run test:merlin`；編譯：`npm run build`。
