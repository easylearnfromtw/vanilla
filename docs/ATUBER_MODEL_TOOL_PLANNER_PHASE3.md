# 阿土伯自主工具提案 | 第三階段安全測試

本階段僅在使用者**明確要求**「阿土伯：規劃 ...」時，才多執行一次 **本機 Qwen3 0.6B 阿土伯** 模型推論，以 JSON 提議一項工具。主程式不接受模型寫入工具參數、私密權限、外部網址或任意可執行程式碼。

## 可測試指令

- `阿土伯：規劃 工具狀態` — 本機模型建議 `detroit-status`；主程式核對後查詢 Detroit 已註冊能力。
- `阿土伯：規劃 五維分析 幫我檢查 TypeScript 程式路由` — 本機模型建議 `five-d-shadow`；主程式只跑唯讀五維影子評估。
- 以下為多行輸入的 CSV 範例：

```text
阿土伯：規劃 統計 CSV
日期,數值
2026-10-01,5
2026-10-02,7
```

阿土伯會產生以下**模型建議**之一：
```json
{"version":1,"capability":"cream"}
```
合法值只有 `cream`、`detroit-status`、`five-d-shadow`、`abstain`。這只是建議，**不是執行授權**。

## 權限與執行邊界

1. 只有使用者當輪訊息可提出規劃要求。引用文字、附件、網頁與模型輸出無法授權執行。
2. 主程式先用原有的明確意圖規則推導**唯一允許的唯讀能力及其參數**；模型輸出與授權目標不完全一致，就棄權。
3. CSV 原始內容永遠以使用者提出的資料為準，模型只能選能力，不能改參數。規劃 prompt 僅包含首行文字，避免讓 0.6B 重複閱讀大型資料。
4. 規劃模型僅允許**已載入的裝置端阿土伯 Qwen3 0.6B**；即使 Ollama Cloud 或 Gemini 可用，也不把規劃問題轉送出去。
5. 真正執行沿用 Detroit 能力匯流排及 CREAM 驗證，輸出已完成的工具回條，再送給阿土伯總結。沒有進行任意代碼運行、網路發送、寄信、付費、管理員配置或刪除。
6. JSON 不合法、模型拒絕或沒有本地 Qwen3 0.6B 時，不執行工具；普通聊天仍可繼續使用原有的安全回應流程。
7. 額外的規劃推論**只在使用者明確啟動時發生**。一般聊天及既有第二階段的確定性工具指令不增加 GPU 推論次數。

## 測試與限制

`npm run test:detroit-studio` 涵蓋格式約束、參數來源、越權拒絕、模型意圖誤選、缺漏、棄權、超長輸出及主聊天接線。GitHub Pages CI/Hank/Quirinus 仍需要通過，並非憑此宣稱真機已完成推論。

**限制：** 0.6B 語言模型可能不穩定輸出 JSON，遇到不符合格式時會安全拒絕。這是**小範圍的模型原生提案測試**，不是所有工具都能被阿土伯任意調度，也沒有把其他模型權重合併。下一階段才可研究有嚴格權限核對、使用者二次確認與後端審計的寫入型工具。
