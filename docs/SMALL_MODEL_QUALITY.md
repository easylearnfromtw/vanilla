# Vanilla / Detroit 小模型品質調校

> 範圍：手機 WebLLM 0.5B–3B，以及有明確可解析參數量的 <=3B 自架 Ollama。
> 這一版是推論時的 **任務編譯與檢索節錄**，不是 SFT、DPO、LoRA 或權重知識蒸餾。

## 主要設計

1. **Merlin 任務卡**：保留使用者問題原文，只輸出最多數百 tokens 的目標、約束及安全提示。讓 4K 上下文留給資料。
2. **證據優先**：按附件/公開來源、授權記憶、程式碼等優先級分配 context；從冗長附件中抽取與問題重合的中文 bigram／英文詞相關段落。
3. **揭露缺漏**：每個被聚焦的來源標記為「節錄」，並於回答卡附註；來源未進入上下文時不可當作已讀取。
4. **維持邊界**：不擅自讀取其他檔案、開啟網路或跳過私密模式；保留 Veritas 對 0.5B 非創作事實問答的能力門檻。
5. **強模型不受影響**：7B+、無法辨識參數量的 Ollama 和雲端模型仍走原有流程。

## 改善的不是什麼

- 小模型的知識、長鏈推理能力與校正能力不會因提示詞等同於 30B。
- 相似詞片段搜尋不是語意 RAG，也不是可靠性評分。召回錯誤或來源自身不實時，小模型仍可能答錯。
- 本模組無法保證任何未實際執行的工具成功，也不能憑空產生網路證據。

## 測試與客觀評估

CI：`npm run test:small-model` 驗證有限 context、相關段落擷取、來源優先級、保留變數、不可用輸入及資料信任邊界。

實際模型測試應針對 0.5B、1.5B、3B，以及 7B/14B 對照組，固定相同題目、相同證據與固定採樣參數；測量：

| 指標 | 測量方式 |
| --- | --- |
| Evidence recall | 重要原始段落是否確實進入送出給模型的 request |
| Answer correctness | 以人工/標準答案核對，區分資訊抽取、數學、程式、常識 |
| Citation accuracy | 引文是否來自實際提供的片段與編號 |
| Unsupported claims | 沒有可靠證據仍給具體數字、時間或聲稱工具成功的比例 |
| End-to-end latency | 首字、完成時間、Ollama/WebLLM 載入與記憶體使用量 |
| Abstention quality | 無答案時是否能保守拒絕，而非編造 |

**不可以**把 CI 通過當作「小模型達到大型模型正確率」的證據。完成 A/B 測試之前，只能說已改善小模型的上下文條件。

## 後續可選升級（未在此 PR 實作）

- 在使用者授權且授權/授權相容資料集下，以大型模型生成「教師」答案，經人工校對和多模型拒絕採樣後執行 LoRA/SFT 蒸餾。
- 建立本機嵌入向量索引和再排序器，替代現在的 lexical matching。
- 針對數學、單位、日程、表格，以 Detroit 確定性工具運算並注入可核對結果，避免讓 0.5B 猜。
- 以真實任務 benchmark 閘門決定小模型哪些問題可以獨立回答，哪些必須要求補充資料或授權較強模型。
