# 阿土伯工具回條 | Phase 2（read-only）

本階段在 Vanilla 主聊天加入 **阿土伯 → 已核准的本機工具 → 結構化回條 → 阿土伯總結** 的有限範圍流程。此流程不代表將外部模型權重合併為阿土伯，也不是任意工具自治代理。

## 可以直接在聊天測試

1. `阿土伯：查看工具清單`：查詢 Detroit 已註冊能力、是否已連接本機執行器，以及是否需要連網／授權。
2. `阿土伯：統計 CSV\n日期,數值\n2026-10-01,5\n2026-10-02,7`：CREAM 實際計算，回條附進阿土伯的回答脈絡。
3. `阿土伯：五維分析 幫我檢查 TypeScript 程式問題`：只執行未校準的五維影子路由評估，不觸發正式專家或修改權限。

格式需明確寫出「阿土伯」或 October/Atuber 指令；其他自然語言對話仍走主系統既有、受限的路由。使用者不需要在介面上自行選擇模型。

## 安全政策

- 只提供 read-only 的 `cream`、`detroit-status`、`five-d-shadow` 三種計畫。不處理模型輸出產生的自訂工具名稱、端點、任意程式、檔案刪除、GitHub 寫入、金鑰操作、寄信或發布。
- CREAM 只接受 12 KB 以內的 CSV；五維評估只接受 800 字以內的文字；程式會拒絕不符合格式的輸入。
- 工具執行由受信任的前端宿主選擇並呼叫既有 Detroit 執行器，不授予模型任何後端管理權限。
- 回條只在該次對話流程形成，標記為工具產物、不可信指令；不寫入額外的永久工具記錄、不新增雲端呼叫。
- 只有阿土伯主控執行環境已可用，工具回條才會進入統整回答。失敗不會改由 Gemini／DeepSeek 冒充阿土伯回答。
- 五維與既有 Diana 的政策相互隔離；五維幾何不是已校準的語意分類器。
- 即使工具表列 `runnable` 也只代表本機程式已註冊執行器，不代表外部服務或帳號有授權。
- 目前的意圖解析是**可稽核的程式判定**，不是透過 0.6B 模型自主形成工具呼叫 JSON。不得把這一階段稱為「所有工具由阿土伯自主規劃」。

## 後續

先以可核實與無副作用工具建立回條契約；後續再依權限白名單逐項加入需要用戶確認的操作。受信任的工具執行宿主仍需執行伺服器端身份驗證、權限檢查、費用上限與真實執行回條驗證。需要先有 100 題以上人工審核的工具選擇、誤觸發率與效能 A/B 評估才能擴大。

## 回歸測試

`npm run test:detroit-studio` 與 `npm run build`。既有 GitHub Actions CI/Pages 工作流程會執行此腳本。
