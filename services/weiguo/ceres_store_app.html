串聯 API · 從零到一

INTEGRATION

請求的完整生命週期

應用程式 → HTTPS API Gateway → 金鑰驗證 → 模型路由 → 推論 → Token 計量 → 回傳。下方使用通用示意路徑，不是已確認的 Vanilla 正式 API 端點。

第一步 · 理解 Endpoint、Key、Model、Token

Endpoint 是伺服器網址；API Key 是請求憑證；Model 指定推論模型；Token 是模型處理文字的計量單位。RPM / TPM 分別表示每分鐘請求數與 Token 數。

第二步 · Python 串聯範例
import os
import requests

base = os.environ["AI_BASE_URL"].rstrip("/")
key = os.environ["AI_API_KEY"]
model = os.environ["AI_MODEL"]
response = requests.post(
    base + "/v1/chat/completions",
    headers={"Authorization": f"Bearer {key}"},
    json={"model": model, "messages": [
        {"role": "user", "content": "請用三句話解釋 API"}
    ]},
    timeout=30,
)
response.raise_for_status()
print(response.json())

僅適用支援 OpenAI 相容 chat/completions 的供應商；Vanilla 是否支援，需以正式文件確認。先安裝 requests。

第三步 · JavaScript（Node.js）範例
const base = process.env.AI_BASE_URL.replace(/\/$/, "");
const response = await fetch(base + "/v1/chat/completions", {
  method: "POST",
  headers: {
    "Authorization": "Bearer " + process.env.AI_API_KEY,
    "Content-Type": "application/json"
  },
  body: JSON.stringify({
    model: process.env.AI_MODEL,
    messages: [{ role: "user", content: "Hello!" }]
  })
});
if (!response.ok) throw new Error("HTTP " + response.status);
console.log(await response.json());

請在伺服器端執行，不要將 API Key 寫入公開前端 JavaScript。

第四步 · 常見錯誤與處理

401：檢查金鑰與驗證格式。403：確認帳號與模型權限。404：核對 API 路徑。429：降低並行、採指數退避與 jitter，遵守 Retry-After。5xx：有限次重試、設定 timeout，避免重複扣費或重複執行副作用。

第五步 · 正式環境安全檢查

使用 HTTPS、後端儲存密鑰、最小權限、金鑰輪替、配額與費率限制、審計日誌、成本警示；對寫入或付款等副作用操作使用冪等鍵。部署前驗證回應結構與模型版本。
